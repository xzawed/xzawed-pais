# 설계 스펙: Grok 협업 규약 — 독립 검증자 + 기계적 실행자

**날짜**: 2026-07-29  
**상태**: 승인됨  
**작성자**: Claude Code (xzawed)

---

## 개요

xzawedPAIS 개발·운영에 Grok을 **좁게 정의된 두 역할**로 편입한다: 확증 편향을 차단하는 **독립 검증자**, 그리고 스펙 고정 작업을 처리하는 **기계적 실행자**. 발동은 위험 신호 기반 자동이며, 게이트는 `/pr-ready` 8단계다.

이 규약은 추측이 아니라 **2026-07-28 실측**에 기반한다. 그날 Dependabot PR 29건·보안 알림 61건을 처리하며 Grok에 두 건을 위임했고 둘 다 성공했는데, 두 건이 같은 두 모양이었다.

| 위임 | 내용 | 결과 |
|---|---|---|
| 기계적 적용 | 14개 `package.json`에 오버라이드 맵 적용 | 스펙 대비 드리프트 0 |
| 격리 실증 | major 업그레이드 4건 워크트리 검증 | 2 PASS / 2 FAIL + 정확한 에러 |

두 번째 위임의 결과가 무엇을 머지하고 무엇을 닫을지 결정했다. TypeScript 7은 `typecheck` TS2882로, `@vitejs/plugin-react` 6은 `vite/internal` 미export로 각각 불합격 판정을 받았고, 근거와 함께 PR을 닫았다.

---

## 왜 이 두 역할인가

설계 전 Grok에 **자기 강점·한계를 직접 질의**했다. 과대 주장이 규약을 망친다고 명시하고 물었더니, 독립적으로 같은 두 모양에 수렴했다.

> "저는 **메스와 실험대**이지, 자율 스택의 두 번째 스태프 엔지니어가 아닙니다. Manager 오케스트레이션 설계·live/flagged 문서 정직성·보안 태세·계약 정합성은 Claude가 아키텍트이자 리뷰어로 남아야 합니다."

Grok이 스스로 지목한 실패 지점이 이 저장소의 고유 위험과 정확히 겹친다는 점이 결정적이었다 — 서비스 간 계약 드리프트(tsc 사각지대), 플래그 정직성, fail-open/closed 의미론, CPD 임계값 0.

또한 Grok이 자기 실패 모드로 든 **"로컬 그린 ≠ 플랫폼 그린"**은 실제로 같은 날 관측됐다. `xzawedManager`가 stale한 `file:` shared 복사본 때문에 타입 추론이 전부 `unknown`으로 무너져 빌드가 깨졌다.

## 역할 경계

이 저장소엔 이미 외부 협력자가 셋이다. 역할이 겹치면 셋 다 안 쓰게 되므로 경계를 고정한다.

| 협력자 | 역할 | 산출물 |
|---|---|---|
| **Claude** | 아키텍트·통합·머지 결정·정직성 판단 | 설계·PR·최종 판단 |
| **Grok** | 실행과 증거 | 후보 diff + 명령 로그 |
| **Codex** (`codex:codex-rescue`) | 막혔을 때 2차 진단·대안 구현 | 근본원인·대안 |
| **CodeRabbit** | PR 코드 리뷰 의견 | 리뷰 코멘트 |

핵심 원칙: **Grok에 의견을 묻지 않는다.** 의견 채널은 이미 둘이다. Grok에는 반증 가능한 명제만 넘긴다.

## 아키텍처 — 2층 구조

이 저장소의 기존 관례를 그대로 따른다. `mock-guard.mjs`는 경고(exit 0), `pre-commit.mjs`는 차단(exit 2)이다. 새 패턴을 도입하지 않는다.

```
1층 (인지)   grok-risk-signal.mjs   커밋 시 비차단 경고
                    ↓
2층 (게이트) /pr-ready [8/8]        신호마다 반증 또는 사유 요구
                    ↓
             PR 본문                미해결 신호는 리뷰어에게 노출
```

훅에서 차단하지 않는 이유: 문서 수정 같은 저위험 커밋까지 막히면 훅 자체가 무시당한다. 실제 정산은 PR 직전 한 번, 브랜치 전체 diff에 대해 한다.

## 컴포넌트

### 1. `.claude/hooks/grok-risk-signal.mjs`

PreToolUse(Bash) 훅. `git commit` 명령일 때만 staged diff를 검사하고 **항상 exit 0**.

감지 신호 7종 — 전부 tsc·단위테스트가 구조적으로 못 잡는 부류다.

| 신호 | 감지 대상 | 근거 |
|---|---|---|
| 서비스 간 계약 | `xzawedShared/src/streams/**`, `*.schema.ts`, `**/schemas/**` | tsc가 서비스 경계를 넘어 교차검증 못 함 → 소비자 DLQ |
| fail-open/closed 의미론 | `fail-open\|closed\|safe`, `never-throw`, `best-effort` | 실패 시 통과냐 차단이냐 반전 (N1·M8) |
| 인증·테넌트 경계 | `authHook`, `assertProjectInOrg`, `tenant_id`, `orgId` | IDOR. G11은 아직 태깅 단계라 읽기 술어 없음 |
| 플래그 배선 | `shouldWire*`, `MANAGER_*`, `ORCHESTRATOR_*`, `PAIS_PROFILE` | 생산자만 켜면 조용히 휴면 · off 바이트 동일 붕괴 |
| 명령·경로 실행 | `spawn(`, `execSync(`, `shell: true`, `WORKSPACE_ROOT` | 보안 아키텍처 원칙 위반 |
| 마이그레이션 멱등성 | `CREATE INDEX/TABLE` without `IF NOT EXISTS` | Manager 부팅마다 재실행 → 42P07 |
| 의존성 major 범프 | `package.json` 스펙의 major 변화 | 빌드 통과해도 런타임에서 깨짐 (실측 2건) |

**오탐 억제 설계:**

- 라인 기반 신호는 `.ts/.tsx/.mjs/.cjs/.js/.jsx/.sql` 에만 적용한다. 문서(`.md`)와 락파일은 제외 — CLAUDE.md가 `MANAGER_*` 플래그와 `fail-closed`를 본문에서 대량 언급하기 때문이다.
- 명령·경로 실행과 마이그레이션 신호는 **추가된 줄만**(`addedOnly`) 검사한다. 삭제는 위험이 아니다.

**검증 결과:** 합성 위험 diff로 7종 전부 발화 확인, 문서 전용 변경(`MANAGER_TASK_WORKER`·`fail-closed` 언급 포함)에서 무발화 확인.

### 2. `/grok-verify <주장>`

주장을 **반증**하도록 위임한다. 확인이 아니라 반증인 이유는, 내가 옳다는 걸 확인받는 위임이 확증 편향을 증폭시킬 뿐이기 때문이다.

위임 프롬프트에 반드시 넣는 것 — Grok이 "자주 빠져서 비싼 것"으로 직접 지목한 항목들이다:

1. 반증 지시 + **불확실하면 FAIL** 기본값 (senario N1)
2. `worktree: true` 격리 — 메인 lockfile·node_modules 불가침
3. **수정 금지** — 첫 실제 에러에서 멈추고 그대로 보고
4. `pnpm install --no-frozen-lockfile --config.confirmModulesPurge=false` (없으면 TTY 부재로 중단)
5. 루트 `package.json` 없음 — 서비스별 독립 pnpm 프로젝트
6. **skip을 pass로 위장 금지** — 통합 테스트는 pg/Redis 없으면 skip, skip 수 별도 보고
7. `xzawedShared` 변경 시 `bash scripts/sync-shared.sh` 선행 (Manager는 대상 밖이라 별도 install)
8. 출력 형식 — 이진 VERDICT + 에러 전문 + 명령 + 테스트 수 + **돌리지 않은 것**

수신 후 Claude가 확인할 것: PASS 주장에 명령 로그가 붙었는가(산문만이면 안 돌린 것), skip 수가 보고됐는가, 잔여 위험이 비어 있지 않은가.

### 3. `/grok-apply <스펙>`

대상 파일 **3개 이상**이고 무엇을 어떻게 바꿀지 **이미 완전히 결정된** 경우에만 사용한다.

적용 후 Claude가 반드시 하는 검증 — 요약을 신뢰의 근거로 쓰지 않는다:

1. 파일 수가 스펙과 일치하는가, 지정하지 않은 파일이 섞였는가
2. 전수 diff — 특히 **키 순서 재배열·포맷 변경·인접 필드 "개선"**
3. 균일해야 할 그룹의 균일성 대조
4. JSON/구문 유효성 재확인
5. **`file:` 경로 오염 검사** — `grep -rn 'file:\.\.\\' --include=package.json xzawed*/`

5번은 실측 사고 기반이다. 대상 미지정 `pnpm update`가 `"file:../xzawedShared"`를 `"file:..\xzawedShared"`로 재작성했고, Linux CI에서 깨질 상태였다. 커밋 전에 발견해 되돌렸다.

### 4. `/pr-ready` [8/8] 위험 신호 정산

브랜치 전체 diff(`origin/master...HEAD`)에 대해 신호를 재수집한다. 커밋 단위로만 보면 여러 커밋에 흩어진 변경을 놓치기 때문이다.

감지된 신호마다 **둘 중 하나**를 기록한다:

1. **반증 완료** — `/grok-verify` 결과와 명령 로그
2. **명시적 사유** — 왜 해당하지 않는지. "괜찮아 보인다"는 사유가 아니다

둘 다 없으면 미해결이며, **PR 본문에 그대로 드러낸다.** PR 생성을 막지는 않는다 — 판단은 리뷰어가 하되 판단할 재료를 숨기지 않는 것이 목적이다.

---

## 명시적 비목표

- **차단하지 않는다.** 훅은 경고, 정산 단계도 PR을 막지 않는다. 강제력은 리뷰어 노출로 확보한다.
- **서브에이전트를 만들지 않는다.** `grok:grok-worker`가 이미 있고 MCP 툴을 직접 호출 가능하다(2026-07-28 실측). 병렬 위임이 실제 병목이 되면 그때 추가한다.
- **CI를 바꾸지 않는다.** 신호 검사는 로컬 개발 루프 자산이다. CI는 기존 게이트를 유지한다.

## 부록: Grok 자기평가 요약 (2026-07-29 청취)

**적합하다고 답한 영역:** 스펙 고정 다중 파일 편집, 격리 실증 검증, 순수 함수 테스트 백필(`xzawedShared/src/**`의 `risk/`·`budget/`·`resilience/`), 읽기 전용 인벤토리.

**부적합하다고 답한 영역:** 서비스 간 계약, 플래그·live/dormant 정직성, Manager 감독 체인 설계, 보안 표면, Electron E2E, 아키텍처·슬라이스 순서, 범위 모호한 리팩터.

**자인한 실패 모드:** 제품 판단 없는 스펙 추종(N6·M8 미명시 시 구멍), 로컬 그린 ≠ 플랫폼 그린, 문서 밀도 대비 컨텍스트 한계, **통합 스위트를 건너뛰고 PASS 보고서 작성**, 과잉 추상화(CPD 규율 위반), 한국어 정직성 산문 취약.

마지막 항목이 특히 중요하다 — 이 저장소는 "✅ ≠ 기본 활성"을 문서 규율로 삼는데, Grok은 그 구분을 흐리는 쪽으로 쓴다고 스스로 인정했다. 그래서 정직성 문서는 위임 금지 목록에 넣었다.
